# 人潮預測架構（現況與路線圖）

## 現況（誠實版本）
- **沒有已訓練的 AI / ML 模型。** 排程是規則式演算法；人潮數字是「模擬」或「觀察混合」。
- `src/engine/crowd.js` 的 `predictCrowd()` 對每個預測都標示來源：
  | 來源 | 意義 | 何時出現 |
  |---|---|---|
  | 觀察 | 由團隊現場紀錄推得 | 該地點、±60 分鐘內 ≥ 3 筆 |
  | 模擬 | 人工設定參數（下課尖峰規則、假設的人數分布） | 觀察 < 3 筆 |
  | 模型 | 訓練後模型預測 | **尚未實作，不會出現** |
- 資料不足時不會裝成預測：UI 顯示「模擬」與原因（例如「僅 2 筆觀察，資料不足」）。
- 3–7 筆時採收縮估計：`pct = k·觀察平均 + (1−k)·模擬`，`k = min(1, n/8)`；同星期的觀察權重 ×2。

## 路線圖（需真實資料才可宣稱）
1. **蒐集**：統一觀察 SOP（同地點同時段、擁擠度 1–5 定義、記錄排隊分鐘）。目標：每個主要地點 × 午餐時段各 ≥ 30 筆，涵蓋多個星期。
2. **特徵**：星期、時段（分鐘）、距上下課時間、是否考試週、天氣（若有）。
3. **基準模型**：先以「同地點同星期同時段的歷史平均」當 baseline；再試簡單回歸／梯度提升。
4. **評估**：留出最近一週當測試集，與「模擬規則」比較 MAE；**未優於 baseline 就不上線、不宣稱有 AI 預測**。
5. **上線**：離線訓練、輸出為靜態係數／小型 JSON，前端載入；來源標示為「模型」，並顯示樣本數與最近更新日期。

## 倫理與限制
不收集個資；觀察為眾包主觀判斷，須在簡報說明誤差來源。
